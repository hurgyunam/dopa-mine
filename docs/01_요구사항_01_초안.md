
## 1. 핵심 철학 및 UI/UX 원칙
* **복잡도 제로:** 앱 실행 시 불필요한 대시보드나 설정 화면 대신 바로 '오늘의 루틴'이 보여야 함.
* **청각 중심 피드백:** 운동 중 화면을 볼 수 없으므로, 모든 상태 변화(준비, 시작, 휴식, 완료)는 명확한 **효과음**으로 전달함.
* **확장성:** 현재는 단일 동작(슈퍼맨)만 하지만, 추후 여러 동작을 조합한 루틴으로 확장 가능한 데이터 구조를 가짐.

---

## 2. 주요 기능 요구사항

### A. 루틴 관리 (Data Structure)
* 루틴은 여러 개의 `Exercise` 아이템으로 구성됨.
* 각 `Exercise` 항목: 이름(예: 슈퍼맨), 버티기 시간(초), 세트 수, 세트 간 휴식 시간.
* 사용자는 언제든지 이 항목의 초 단위와 세트 수를 수정하거나, 새로운 운동을 리스트에 추가/삭제할 수 있음.

### B. 타이머 엔진 (Audio-Visual)
* **준비 시간 (3초):** 운동 시작 전 자세를 잡을 수 있는 카운트다운.
* **운동 진행:** 설정된 초 동안 타이머 작동.
* **휴식 시간:** 세트 사이 휴식.
* **효과음 트리거:**
    * 3, 2, 1 카운트다운: 짧은 비프음
    * 운동 시작: 높은 톤의 벨소리
    * 휴식 시작: 낮은 톤의 벨소리
    * 전체 루틴 종료: 긴 성공 사운드

### C. 최소주의 UI 구성 (Single Page 추천)
* **메인 화면:** 현재 활성화된 루틴 리스트가 카드 형태로 나열됨.
* **편집 모드:** 각 카드를 클릭하면 시간과 세트 수를 즉시 변경할 수 있는 바텀 시트(Bottom Sheet) 오픈.
* **실행 화면:** 현재 운동 이름, 남은 시간, 현재 세트/총 세트 정보를 아주 큰 폰트로 표시.

## 3. 기술 스택 및 제약 사항
* **Framework:** Flutter (Clean Architecture 지향)
* **State Management:** Provider 또는 Bloc (가장 자신 있는 것으로 선택 요청)
* **Storage:** `shared_preferences`를 사용하여 사용자가 수정한 루틴 정보 로컬 저장.
* **Audio:** `audioplayers` 패키지 사용.
